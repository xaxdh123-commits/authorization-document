# 委托生产授权资料平台需求设计

日期：2026-08-05  
状态：设计已由用户确认，待文档复核

## 1. 项目目标

建设一套面向“客户/品牌方委托公司或指定工厂生产物料”场景的授权资料平台。内部客服在后台创建业务单、选择授权书模板和所需凭证，系统生成专属 H5 链接。客户通过链接分步填写资料、上传凭证、预览并签署授权书。内部人员逐项审核，可驳回并要求补件；全部通过后生成最终 PDF、归档并关闭客户链接。

首期采用 Node.js 后端、React 后台、React H5、PostgreSQL、PM2 和服务器本地文件存储；后续文件目录可挂载 NAS。

## 2. 首期范围

### 2.1 包含

- 复用现有系统 Token 和 `getInfo` 完成后台身份校验。
- 根据现有系统 `roles[].roleKey` 进行平台角色映射。
- 管理动态资料项库，可配置字段、上传要求、必填规则、格式、大小和说明。
- 管理多套授权书模板，并按工厂、部门或业务场景分类。
- 后台可视化编辑授权书，支持动态变量、多物料循环表格和签章位置。
- 客服创建包含多个物料明细的业务单，选择模板及本次所需凭证。
- 支持人工输入/粘贴报价信息，并预留报价来源编号和快照数据结构；首期不交付自动导入接口。
- 生成随机、不可猜测、可失效的客户 H5 链接。
- H5 自动保存草稿，客户可通过原链接继续填写。
- 客户可手写签名，或上传印章图片并去除背景后覆盖到 PDF 指定位置。
- 后台逐项审核、填写驳回原因、要求客户补件并进行复审。
- 保留文件、回答、签署和审核的每一版历史记录。
- 完成时生成并锁定最终 PDF、关闭客户链接。
- 工作台、业务单查询、审核列表和操作审计日志。

### 2.2 暂不包含

- 短信、邮件、企业微信或微信自动通知；首期由客服复制链接和驳回说明后人工发送。
- 第三方可信电子签约的实名认证、数字证书、可信时间戳和证据报告。
- 与报价系统数据库或 API 的正式集成。
- 类似 Microsoft Word 的全部高级排版能力。
- 微服务部署、独立消息中间件或对象存储。

系统须预留签署模式、第三方签署任务 ID、回调状态和证据报告等扩展字段，以便后续接入可信电子签平台。

## 3. 用户与权限

### 3.1 后台身份来源

后台不建立独立账号和密码体系。用户进入平台时携带现有系统登录 Token，新平台后端使用该 Token 调用现有系统 `getInfo`。校验成功后，只使用并缓存必要字段，例如用户 ID、姓名、部门、角色和权限摘要。

不得保存或记录 `getInfo` 返回的密码、第三方账号密码、MAC 地址等非必要敏感信息。鉴权服务不可用时，拒绝新的后台写操作并清晰提示稍后重试。

### 3.2 平台能力

- 管理员：模板、资料项、角色映射、系统设置、全部业务数据和审计日志。
- 客服：创建和编辑业务单、生成或关闭链接、查看客户进度、复制驳回说明。
- 审核员：逐项审核、驳回、复审、确认完成。

平台管理员将现有系统的 `roleKey` 映射到上述能力。`admin` 默认拥有全部能力，其他映射可后期配置。同一现有角色可以映射多个平台能力。

首期能力矩阵如下：

| 能力 | 管理员 | 客服 | 审核员 |
|---|---:|---:|---:|
| 查看本人创建/负责的业务单 | 是 | 是 | 是 |
| 查看部门业务单 | 是 | 可配置 | 可配置 |
| 查看全部业务单 | 是 | 否 | 可配置 |
| 创建、编辑草稿、管理客户链接 | 是 | 是 | 否 |
| 查看普通资料文件 | 是 | 本人/本部门业务单 | 分配给本人/本部门的业务单 |
| 查看身份证等敏感资料 | 是 | 默认否，可单独配置 | 审核所需时是 |
| 逐项审核和驳回 | 是 | 否 | 是 |
| 确认完成、关闭业务单、重试最终 PDF | 是 | 否 | 是 |
| 管理资料项和模板草稿 | 是 | 否 | 否 |
| 发布模板、配置角色映射、查看全量审计日志 | 是 | 否 | 否 |

平台能力固定，角色映射只决定现有 `roleKey` 获得哪些能力。数据范围为 `SELF`、`DEPT`、`ALL` 三档，默认客服为 `SELF`，审核员为 `DEPT`，管理员为 `ALL`；角色映射可将客服或审核员调整为更小或更大范围。用户存在多个角色时取能力与数据范围并集。未配置的角色默认无权进入平台。

业务单包含 `creatorUserId`、`ownerUserId`、`ownerDeptId`、`reviewerUserId` 和 `reviewerDeptId`。创建时客服自动成为负责人，其当前部门成为负责部门。管理员可在任何非终态改派负责人或审核员；拥有该业务单 `DEPT` 数据范围的客服可在本部门内改派负责人，审核员不能自行改派。业务单首次提交时，若未指定审核员，则进入负责部门的未分配审核队列；该部门具有审核能力的用户均可见并可领取，领取使用原子更新避免多人同时占用。管理员可查看和领取所有未分配业务单。`SELF` 对客服表示本人创建或负责，对审核员表示本人已领取；`DEPT` 根据对应负责部门或审核部门判断。所有分配、领取和改派均写审计日志。

### 3.3 客户访问

客户无需注册账号，仅凭业务单专属链接进入。链接令牌必须使用密码学安全随机数生成，数据库只保存令牌哈希。链接可设置截止时间、手动停用、续期或重新生成；重新生成后旧令牌立即失效。业务单完成或关闭后链接不可再访问。

令牌至少包含 128 位随机熵；默认不设置固定天数，而以业务单截止时间为上限。令牌校验失败统一返回无效或已失效页面，不能泄露业务单是否存在。续期只修改截止时间，停用立即拒绝访问，重新生成同时撤销旧令牌；这些动作不改变业务主状态，但必须写审计日志。已完成或已关闭业务单禁止重新开放链接。

### 3.4 `getInfo` 最低契约

- 后台请求按配置的请求头携带原 Token；新平台后端将其透传给配置的 `getInfo` URL。
- HTTP 200 且响应 `code = 200`、包含 `user.userId` 和至少一个有效 `roles[].roleKey` 时视为认证成功。
- HTTP 401/403，或业务 `code` 表示未登录/Token 过期时，清除平台会话缓存并向前端返回统一 401。
- 上游超时默认 3 秒；网络错误、5xx 或无法解析的响应返回 503，不当作无权限或 Token 过期。
- 成功结果最多缓存 60 秒，缓存键为 Token 摘要，不保存原 Token；所有写操作在缓存过期后重新验证。权限撤销允许最多 60 秒传播延迟。
- 上游不可用时，仅允许在已有 60 秒有效缓存内执行读操作；写操作全部拒绝。不得使用过期缓存延长会话。
- 只接受 `userId`、姓名、部门和角色等白名单字段，忽略密码及其他非必要字段。

## 4. 核心业务流程

1. 管理员维护资料项库、授权书模板、模板变量、签章位置及角色映射。
2. 客服创建业务单，人工录入或粘贴客户、联系人、工厂/部门和多个物料明细。
3. 客服选择一个已发布的授权书模板。授权书必选；其他凭证从资料项库按本单需求勾选。
4. 系统保存报价和模板版本快照，生成客户专属 H5 链接。
5. 客服一键复制链接并通过微信发送给客户。
6. 客户确认生产信息、填写动态问卷、上传凭证；系统自动保存草稿。
7. 客户预览授权书，选择手写签名或上传印章图片。系统生成透明签章图并覆盖到模板指定位置。
8. 客户勾选资料真实性与授权意愿声明，正式提交。
9. 审核员按授权书和各凭证逐项通过或驳回；驳回原因必填。
10. 客服复制驳回说明发送客户。客户通过原链接只修改被驳回项目，再次提交复审。
11. 全部项目通过后进入“待生成最终文件”，立即冻结客户编辑，但尚不关闭业务单。
12. 最终 PDF 生成并完成哈希与可读取性校验后，系统原子地进入“已完成”并关闭客户链接。生成失败时保持“最终文件生成失败”，由管理员或审核员重试。

## 5. 状态模型

主状态按以下顺序流转：

`草稿 → 待客户填写 → 客户填写中 → 待审核 → 需补件 → 待复审 → 待生成最终文件 → 已完成`

`待生成最终文件 → 最终文件生成失败 → 待生成最终文件` 为可重试分支。

规则：

- 客服创建并首次生成链接：`草稿 → 待客户填写`；客户首次保存：`待客户填写 → 客户填写中`。
- 客户正式提交且必填校验通过：`待客户填写/客户填写中 → 待审核`。
- 审核员驳回任一项：`待审核/待复审 → 需补件`；客户仅完成驳回项并再次提交：`需补件 → 待复审`。
- 审核员执行“确认审核通过”：`待审核/待复审 → 待生成最终文件`，前置条件为所有资料项已通过、签署声明存在、签章位校验通过。
- Worker 成功生成并验证最终 PDF：`待生成最终文件 → 已完成`；任务耗尽重试次数：`待生成最终文件 → 最终文件生成失败`；管理员或审核员点击重试：`最终文件生成失败 → 待生成最终文件`。
- 管理员或审核员可关闭任一非终态业务单；客服只能关闭自己创建且尚未正式提交的业务单。关闭原因必填。
- `已完成` 和 `已关闭` 为终态，默认只读。
- 不允许绕过客户正式提交直接进入审核，也不允许存在驳回项时完成业务单。
- 每次状态变化记录操作者、时间、来源、前后状态和备注。
- PDF 失败不撤销已通过的审核项，但业务单不能进入 `已完成`，客户仍被冻结，链接展示“资料审核已通过，文件处理中”。

每个资料项另有 `待填写、待审核、已通过、已驳回` 状态。审核最小粒度为“资料项”：一个资料项包含的字段和文件作为一个审核单元。审核员可在原因中指明具体字段或文件，但驳回后该资料项整体重新开放，其他已通过资料项保持只读。授权书被驳回时，旧签署记录保留，新版本必须重新预览、重新签署并再次确认声明。

## 6. 后台功能

### 6.1 工作台

展示草稿、待客户、待审核、需补件和已完成数量，以及最近业务单和超期业务单。统计需按角色和数据范围过滤。

### 6.2 业务单管理

- 按编号、客户、工厂/部门、客服、状态和日期筛选。
- 创建、编辑草稿、复制链接、续期、停用、重新生成、关闭和查看业务单；管理员或具备范围的客服可按权限执行负责人改派。
- 详情页签：基本信息、物料明细、客户问卷、资料文件、授权书、审核记录、操作日志。
- 一个业务单支持多条物料明细：商品名称、规格、数量、材质、工艺及可选价格字段。
- 数据进入平台后形成快照，不随原报价系统后续修改而改变。

### 6.3 资料项配置

资料项支持文本、长文本、单选、多选、日期、数字、文件和图片等类型，可配置标题、说明、示例、必填、允许类型、单文件大小、数量及排序。授权书为系统内置必选项目，不能从业务单移除。

资料项采用草稿/发布版本。发布后版本不可修改；改名、改规则或删除通过创建新版本完成，停用只影响新业务单。业务单保存所选资料项版本快照。资料项字段具有不可变机器键、显示名称、类型、默认值和校验规则；机器键发布后不得改名，避免历史回答失配。发布前必须验证机器键唯一、必填规则完整、文件限制有效。

### 6.4 授权书模板

模板编辑器首期支持：

- A4 页面、标题、段落、字体、对齐、间距、页眉、页脚和分页。
- 表格、图片、固定文本和动态变量。
- 多物料循环表格，可按业务单明细自动增加行。
- 签名/印章占位区域及尺寸约束。
- 预览、草稿、发布、复制和停用。

每次发布生成不可变模板版本。业务单引用具体版本并保存渲染快照；模板后来修改不影响历史业务单。

模板变量分为客户、业务单、物料、系统日期和动态问卷五类，均有稳定机器键与明确类型。多物料变量只能用于循环表格。发布前执行静态校验：变量必须存在、类型与组件匹配、必填变量有值来源、签章位规则完整；存在未知或已停用变量时禁止发布。删除或改名通过新版本完成，不迁移或改写历史模板。

每个模板首期支持一个“甲方签署人”，可配置一个或多个签章位。每个签章位配置用途、页码/锚点、允许位置、尺寸及是否必填。签署方式为“手写签名”或“上传印章”二选一，并将同一种签署资源应用到所有标记为甲方且必填的签章位；首期不支持同一业务单组合使用两种方式，也不支持多人会签。

### 6.5 审核

审核员从部门未分配队列领取或接收管理员分配的业务单，逐项查看材料和版本，执行通过或驳回。驳回原因必填，可针对具体文件或字段。复审时突出显示客户本次修改内容。全部资料通过后，审核员执行“确认审核通过”，业务单随后进入最终 PDF 生成阶段。

## 7. 客户 H5

H5 采用四步向导：

1. 确认客户、联系人、多条物料信息并填写动态字段。
2. 按清单上传资料，显示格式、大小、数量、示例和上传进度。
3. 预览授权书，手写签名或上传印章，调整允许范围内的位置和尺寸并再次预览。
4. 勾选真实性与授权声明，正式提交并查看提交结果。

草稿应自动保存；刷新、退出和重新打开原链接后能够继续。多窗口编辑使用版本号避免静默覆盖。提交后内容只读；进入补件状态后只开放被驳回项目，并显示驳回原因。

## 8. PDF 与签章处理

模板编辑器保存结构化 JSON，同时在发布时保存可渲染 HTML 快照。Node.js 后台任务使用 Chromium 将 HTML 渲染为 PDF，保证预览与最终文件一致。

普通签署支持：

- Canvas 手写签名，允许清除和重新签写。
- 上传印章图片，使用图像处理去除浅色背景、裁剪透明边缘，并允许客户确认处理结果。
- 签名或印章只能在模板定义的签章区域内调整位置和尺寸。

保留原始上传图、处理后的透明图、签署前 PDF、最终 PDF、文件哈希、生成时间和关联业务版本。若自动抠图失败，应保留原图并允许重传或切换为手写签名。

首期普通签署不宣称等同于第三方可靠电子签名。界面与声明不得造成误导。

签署前必须展示本次待签 PDF 的完整预览及文件摘要。客户确认后生成签署记录，记录签署方式、签署资源版本、PDF 哈希、签署时间、客户端 IP 和用户代理。任一会影响授权书内容的补件或后台变更都会使原签署记录失效，并要求重新签署。

## 9. 数据与存储

### 9.1 PostgreSQL

PostgreSQL 地址、端口、数据库名、账号和密码全部通过环境变量配置，不进入代码仓库；当前部署环境可指向已有数据库服务。

建议核心实体：

- 后台用户缓存与角色映射
- 资料项定义及版本
- 授权书模板及版本
- 业务单、物料明细和报价快照
- 业务单资料要求、回答及回答版本
- 文件元数据及文件版本
- 签署记录与签章资源
- 审核记录
- 客户访问令牌
- PDF 任务
- 审计事件

关系、状态、编号和常用筛选字段使用标准列与外键；动态字段定义、编辑器文档和灵活快照使用 `JSONB`，避免把全部数据无差别存入 JSON。

### 9.2 文件

首期保存到服务器独立数据目录，后续该目录挂载 NAS。数据库只保存存储键和相对路径，不保存固定绝对路径。

文件必须随机重命名，校验扩展名、真实 MIME、单文件大小、数量和业务单总量。文件下载通过后端权限校验，不能直接公开磁盘目录。法人身份证等敏感文件遵循最小权限展示，日志不得记录文件内容或完整证件号码。

默认限制可由管理员调整：单文件 20 MB，每个资料项最多 10 个文件，每个业务单总量 200 MB。首期允许 PDF、PNG、JPEG；其他类型需显式开启。应用层做类型和大小校验，部署侧应配置杀毒扫描或隔离区；若上线时没有恶意文件扫描，必须在上线风险清单中记录并限制文件只下载不在线执行。

业务数据、最终 PDF、审计记录和所有历史版本默认保留 5 年；关闭业务单同样进入保留期，不立即删除。到期删除功能首期不自动执行，后续由管理员审批任务实现。数据库每日备份，文件目录每日增量备份；目标恢复点不超过 24 小时，目标恢复时间不超过 8 小时。备份使用独立凭据和最小权限，恢复演练至少每季度一次。

## 10. 系统架构

采用单仓库模块化单体：

- React 管理后台。
- React 客户 H5。
- Node.js/NestJS REST API。
- PDF/图像后台 Worker。
- PostgreSQL 数据库。
- 本地/NAS 文件存储适配层。

后端按鉴权与角色、模板、业务单、动态问卷、文件、PDF、签署、审核和审计模块划分。模块通过明确接口交互，不直接访问其他模块内部数据访问层。

建议技术组合：

- 前端：React、TypeScript、Vite、Ant Design、Ant Design Mobile。
- 模板编辑：Tiptap/ProseMirror 扩展。
- 后端：Node.js、NestJS、Prisma、OpenAPI。
- 后台任务：pg-boss，直接使用 PostgreSQL，首期不额外部署 Redis。
- PDF：Playwright/Chromium。
- 图像：Sharp。
- 进程：PM2 管理 API 和 Worker，提供自动重启和日志轮转。

## 11. 外部系统集成

### 11.1 鉴权系统

后台请求携带现有 Token。新平台后端调用现有系统 `getInfo` 并根据返回角色映射平台能力。具体接口地址、请求头名称、缓存时长和失败策略通过配置管理。

### 11.2 报价系统

首期实际交付仅包含人工输入/粘贴，以及内部数据结构中的 `sourceType`、`sourceQuoteId`、`sourceSnapshot` 字段；不交付报价交换端点。由于不同子域不能直接共享普通 `localStorage`，后续正式自动带入方案使用短期、一次性数据交换令牌：报价系统将资料暂存到受控接口并跳转到新平台，新平台使用令牌换取资料。URL 不传递客户资料、价格或其他敏感明文。

## 12. 错误处理与恢复

- 表单保存返回明确版本号。首期采用乐观锁：版本冲突返回 HTTP 409，客户端保留本地未提交内容并要求用户刷新查看服务器最新版后重新填写，不做自动字段合并，也不静默覆盖。
- 文件上传显示单文件进度，失败可重试，已成功文件不重复上传。
- PDF 任务具备幂等键、有限重试和失败原因；PM2 重启后未完成任务可恢复。
- 最终完成动作使用事务并校验所有资料已通过，避免部分完成。
- 同一回调或重复提交不能生成多份不一致的最终记录。
- getInfo、数据库、文件目录或 Chromium 不可用时，显示可理解的错误，不泄露堆栈和内部路径。

## 13. 测试策略

- 单元测试：状态转换、角色映射、令牌、动态规则、模板变量、文件校验和签章边界。
- 集成测试：PostgreSQL、getInfo、文件读写、PDF Worker、模板版本和审核版本。
- 端到端测试：客服创建、客户草稿、上传签署、驳回补件、复审完成和链接关闭。
- 安全测试：伪造或过期令牌、越权下载、路径穿越、恶意文件名、虚假 MIME、超限文件和敏感日志。
- PDF 视觉回归：典型单页、多页、多物料、分页表格、长文本和签章位置。每个已批准模板版本用固定测试数据生成基准 PDF，并固定 Chromium 主版本、字体包、纸张与边距；渲染页转为 144 DPI 图片逐像素比较，忽略单通道差值不超过 8 的像素，剩余差异像素占比不得超过 0.5%。超阈值必须人工批准新基线并记录原因。

## 14. 首期验收标准

1. 测试人员使用预置模板、3 条物料和 3 个资料项，在不上传客户文件的前提下，连续 5 次均能在 3 分钟内创建业务单并复制链接。
2. 发布时建立并归档兼容性矩阵，至少覆盖当时最新两个稳定主版本的桌面/Android Chrome、iOS 最新和前一主要版本的 Safari，以及生产环境目标客户使用的微信内置浏览器版本；在这些明确记录的版本中填写至少 10 个字段并上传 3 个文件，刷新、退出并重新打开后，已确认保存的字段和文件 100% 恢复，且不存在阻断流程的 P0/P1 缺陷。
3. 针对单页、多页、3 条与 20 条物料用例，所有必填变量均有值，多物料表格不丢行；签章图外接矩形完全位于模板允许区域；预览与最终 PDF 使用第 13 节规定的固定基线和像素比较方法，差异像素占比不超过 0.5%。
4. 一个业务单包含 3 个资料项时，驳回其中 1 项后，客户只能编辑该项；另外 2 项保持只读。补件前后回答、文件、签署和审核记录均能按时间查看与下载。
5. 全部审核通过后进入 `待生成最终文件`；只有最终 PDF 可读取且其 SHA-256 与数据库记录一致时进入 `已完成`。进入完成态后原客户链接在 1 秒内失效。
6. 在测试环境强制终止并重启 API 与 Worker，已提交业务数据和文件无丢失，未完成 PDF 任务在 60 秒内恢复处理，且不生成重复最终记录。
7. 使用 `SELF`、`DEPT`、`ALL` 三组测试账号覆盖查看、下载、审核、关闭、模板发布和审计日志操作；所有不在能力矩阵及数据范围内的请求均返回 403，不能仅靠隐藏前端按钮控制。
8. 自动化安全用例覆盖过期、伪造和已撤销令牌，跨业务单文件 ID、路径穿越文件名、扩展名/MIME 不一致、超限文件及日志敏感信息；所有越权与非法输入被拒绝，响应不包含磁盘路径、堆栈、原 Token 或完整证件号。

## 15. 部署与配置

PM2 至少运行两个进程：API 和 PDF Worker。React 后台与 H5 构建为静态资源，由现有反向代理或 Node.js 静态服务发布。生产配置通过环境变量提供，包括数据库连接、鉴权接口、Token 请求头、文件根目录、外部访问域名、链接默认截止策略和日志级别。

上线前必须确认 PostgreSQL 备份、本地/NAS 文件备份、磁盘容量监控、日志轮转、HTTPS、反向代理上传限制和 Chromium 运行依赖。
