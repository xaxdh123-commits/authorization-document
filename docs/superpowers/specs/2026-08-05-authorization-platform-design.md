# 委托生产授权资料平台需求设计

日期：2026-08-05  
状态：设计已由用户确认，待文档复核

## 1. 项目目标

建设一套面向“客户/品牌方委托公司或指定工厂生产物料”场景的授权资料平台。内部客服在后台创建业务单、选择授权书模板和所需凭证，系统生成专属 H5 链接。客户通过链接分步填写资料、上传凭证、预览并签署授权书。内部人员逐项审核，可驳回并要求补件；全部通过后生成最终 PDF、归档并关闭客户链接。

首期采用 Node.js 后端、React 后台、React H5、PostgreSQL、PM2 和服务器本地文件存储；后续文件目录可挂载 NAS。

## 2. 首期范围

### 2.1 包含

- 复用现有系统 Token 和 `getInfo` 完成后台身份校验。
- 根据现有系统 `roles[].roleKey` 进行平台角色映射。
- 管理动态资料项库，可配置字段、上传要求、必填规则、格式、大小和说明。
- 管理多套授权书模板，并按工厂、部门或业务场景分类。
- 后台可视化编辑授权书，支持动态变量、多物料循环表格和签章位置。
- 客服创建包含多个物料明细的业务单，选择模板及本次所需凭证。
- 支持人工输入/粘贴报价信息，并预留从现有报价系统通过短期令牌导入数据的接口。
- 生成随机、不可猜测、可失效的客户 H5 链接。
- H5 自动保存草稿，客户可通过原链接继续填写。
- 客户可手写签名，或上传印章图片并去除背景后覆盖到 PDF 指定位置。
- 后台逐项审核、填写驳回原因、要求客户补件并进行复审。
- 保留文件、回答、签署和审核的每一版历史记录。
- 完成时生成并锁定最终 PDF、关闭客户链接。
- 工作台、业务单查询、审核列表和操作审计日志。

### 2.2 暂不包含

- 短信、邮件、企业微信或微信自动通知；首期由客服复制链接和驳回说明后人工发送。
- 第三方可信电子签约的实名认证、数字证书、可信时间戳和证据报告。
- 与报价系统数据库或 API 的正式集成。
- 类似 Microsoft Word 的全部高级排版能力。
- 微服务部署、独立消息中间件或对象存储。

系统须预留签署模式、第三方签署任务 ID、回调状态和证据报告等扩展字段，以便后续接入可信电子签平台。

## 3. 用户与权限

### 3.1 后台身份来源

后台不建立独立账号和密码体系。用户进入平台时携带现有系统登录 Token，新平台后端使用该 Token 调用现有系统 `getInfo`。校验成功后，只使用并缓存必要字段，例如用户 ID、姓名、部门、角色和权限摘要。

不得保存或记录 `getInfo` 返回的密码、第三方账号密码、MAC 地址等非必要敏感信息。鉴权服务不可用时，拒绝新的后台写操作并清晰提示稍后重试。

### 3.2 平台能力

- 管理员：模板、资料项、角色映射、系统设置、全部业务数据和审计日志。
- 客服：创建和编辑业务单、生成或关闭链接、查看客户进度、复制驳回说明。
- 审核员：逐项审核、驳回、复审、确认完成。

平台管理员将现有系统的 `roleKey` 映射到上述能力。`admin` 默认拥有全部能力，其他映射可后期配置。同一现有角色可以映射多个平台能力。

### 3.3 客户访问

客户无需注册账号，仅凭业务单专属链接进入。链接令牌必须使用密码学安全随机数生成，数据库只保存令牌哈希。链接可设置截止时间、手动停用、续期或重新生成；重新生成后旧令牌立即失效。业务单完成或关闭后链接不可再访问。

## 4. 核心业务流程

1. 管理员维护资料项库、授权书模板、模板变量、签章位置及角色映射。
2. 客服创建业务单，人工录入或粘贴客户、联系人、工厂/部门和多个物料明细。
3. 客服选择一个已发布的授权书模板。授权书必选；其他凭证从资料项库按本单需求勾选。
4. 系统保存报价和模板版本快照，生成客户专属 H5 链接。
5. 客服一键复制链接并通过微信发送给客户。
6. 客户确认生产信息、填写动态问卷、上传凭证；系统自动保存草稿。
7. 客户预览授权书，选择手写签名或上传印章图片。系统生成透明签章图并覆盖到模板指定位置。
8. 客户勾选资料真实性与授权意愿声明，正式提交。
9. 审核员按授权书和各凭证逐项通过或驳回；驳回原因必填。
10. 客服复制驳回说明发送客户。客户通过原链接只修改被驳回项目，再次提交复审。
11. 全部项目通过后，系统锁定数据、回答、模板和文件快照，生成最终 PDF 并关闭客户链接。

## 5. 状态模型

主状态按以下顺序流转：

`草稿 → 待客户填写 → 客户填写中 → 待审核 → 需补件 → 待复审 → 已完成`

规则：

- `需补件` 可循环进入 `待复审`，直到全部通过。
- 任一未完成状态可由有权限人员关闭，关闭原因必填。
- `已完成` 和 `已关闭` 为终态，默认只读。
- 不允许绕过客户正式提交直接进入审核，也不允许存在驳回项时完成业务单。
- 每次状态变化记录操作者、时间、来源、前后状态和备注。
- PDF 后台任务失败不改变业务审核结果；系统显示生成失败并允许重试。

每个资料项另有 `待填写、待审核、已通过、已驳回` 状态。补件只开放已驳回项，已通过内容保持只读。

## 6. 后台功能

### 6.1 工作台

展示草稿、待客户、待审核、需补件和已完成数量，以及最近业务单和超期业务单。统计需按角色和数据范围过滤。

### 6.2 业务单管理

- 按编号、客户、工厂/部门、客服、状态和日期筛选。
- 创建、编辑草稿、复制链接、续期、停用、重新生成、关闭和查看业务单。
- 详情页签：基本信息、物料明细、客户问卷、资料文件、授权书、审核记录、操作日志。
- 一个业务单支持多条物料明细：商品名称、规格、数量、材质、工艺及可选价格字段。
- 数据进入平台后形成快照，不随原报价系统后续修改而改变。

### 6.3 资料项配置

资料项支持文本、长文本、单选、多选、日期、数字、文件和图片等类型，可配置标题、说明、示例、必填、允许类型、单文件大小、数量及排序。授权书为系统内置必选项目，不能从业务单移除。

### 6.4 授权书模板

模板编辑器首期支持：

- A4 页面、标题、段落、字体、对齐、间距、页眉、页脚和分页。
- 表格、图片、固定文本和动态变量。
- 多物料循环表格，可按业务单明细自动增加行。
- 签名/印章占位区域及尺寸约束。
- 预览、草稿、发布、复制和停用。

每次发布生成不可变模板版本。业务单引用具体版本并保存渲染快照；模板后来修改不影响历史业务单。

### 6.5 审核

审核员逐项查看材料和版本，执行通过或驳回。驳回原因必填，可针对具体文件或字段。复审时突出显示客户本次修改内容。全部资料通过后，审核员执行“确认完成”。

## 7. 客户 H5

H5 采用四步向导：

1. 确认客户、联系人、多条物料信息并填写动态字段。
2. 按清单上传资料，显示格式、大小、数量、示例和上传进度。
3. 预览授权书，手写签名或上传印章，调整允许范围内的位置和尺寸并再次预览。
4. 勾选真实性与授权声明，正式提交并查看提交结果。

草稿应自动保存；刷新、退出和重新打开原链接后能够继续。多窗口编辑使用版本号避免静默覆盖。提交后内容只读；进入补件状态后只开放被驳回项目，并显示驳回原因。

## 8. PDF 与签章处理

模板编辑器保存结构化 JSON，同时在发布时保存可渲染 HTML 快照。Node.js 后台任务使用 Chromium 将 HTML 渲染为 PDF，保证预览与最终文件一致。

普通签署支持：

- Canvas 手写签名，允许清除和重新签写。
- 上传印章图片，使用图像处理去除浅色背景、裁剪透明边缘，并允许客户确认处理结果。
- 签名或印章只能在模板定义的签章区域内调整位置和尺寸。

保留原始上传图、处理后的透明图、签署前 PDF、最终 PDF、文件哈希、生成时间和关联业务版本。若自动抠图失败，应保留原图并允许重传或切换为手写签名。

首期普通签署不宣称等同于第三方可靠电子签名。界面与声明不得造成误导。

## 9. 数据与存储

### 9.1 PostgreSQL

数据库位于 `192.168.22.208:5432`，数据库名、账号和密码通过环境变量配置，不进入代码仓库。

建议核心实体：

- 后台用户缓存与角色映射
- 资料项定义及版本
- 授权书模板及版本
- 业务单、物料明细和报价快照
- 业务单资料要求、回答及回答版本
- 文件元数据及文件版本
- 签署记录与签章资源
- 审核记录
- 客户访问令牌
- PDF 任务
- 审计事件

关系、状态、编号和常用筛选字段使用标准列与外键；动态字段定义、编辑器文档和灵活快照使用 `JSONB`，避免把全部数据无差别存入 JSON。

### 9.2 文件

首期保存到服务器独立数据目录，后续该目录挂载 NAS。数据库只保存存储键和相对路径，不保存固定绝对路径。

文件必须随机重命名，校验扩展名、真实 MIME、单文件大小、数量和业务单总量。文件下载通过后端权限校验，不能直接公开磁盘目录。法人身份证等敏感文件遵循最小权限展示，日志不得记录文件内容或完整证件号码。

## 10. 系统架构

采用单仓库模块化单体：

- React 管理后台。
- React 客户 H5。
- Node.js/NestJS REST API。
- PDF/图像后台 Worker。
- PostgreSQL 数据库。
- 本地/NAS 文件存储适配层。

后端按鉴权与角色、模板、业务单、动态问卷、文件、PDF、签署、审核和审计模块划分。模块通过明确接口交互，不直接访问其他模块内部数据访问层。

建议技术组合：

- 前端：React、TypeScript、Vite、Ant Design、Ant Design Mobile。
- 模板编辑：Tiptap/ProseMirror 扩展。
- 后端：Node.js、NestJS、Prisma、OpenAPI。
- 后台任务：pg-boss，直接使用 PostgreSQL，首期不额外部署 Redis。
- PDF：Playwright/Chromium。
- 图像：Sharp。
- 进程：PM2 管理 API 和 Worker，提供自动重启和日志轮转。

## 11. 外部系统集成

### 11.1 鉴权系统

后台请求携带现有 Token。新平台后端调用现有系统 `getInfo` 并根据返回角色映射平台能力。具体接口地址、请求头名称、缓存时长和失败策略通过配置管理。

### 11.2 报价系统

首期允许人工输入和复制。由于不同子域不能直接共享普通 `localStorage`，正式自动带入方案使用短期、一次性数据交换令牌：报价系统将资料暂存到受控接口并跳转到新平台，新平台使用令牌换取资料。URL 不传递客户资料、价格或其他敏感明文。

## 12. 错误处理与恢复

- 表单保存返回明确版本号，版本冲突时提示刷新或合并，不静默覆盖。
- 文件上传显示单文件进度，失败可重试，已成功文件不重复上传。
- PDF 任务具备幂等键、有限重试和失败原因；PM2 重启后未完成任务可恢复。
- 最终完成动作使用事务并校验所有资料已通过，避免部分完成。
- 同一回调或重复提交不能生成多份不一致的最终记录。
- getInfo、数据库、文件目录或 Chromium 不可用时，显示可理解的错误，不泄露堆栈和内部路径。

## 13. 测试策略

- 单元测试：状态转换、角色映射、令牌、动态规则、模板变量、文件校验和签章边界。
- 集成测试：PostgreSQL、getInfo、文件读写、PDF Worker、模板版本和审核版本。
- 端到端测试：客服创建、客户草稿、上传签署、驳回补件、复审完成和链接关闭。
- 安全测试：伪造或过期令牌、越权下载、路径穿越、恶意文件名、虚假 MIME、超限文件和敏感日志。
- PDF 视觉回归：典型单页、多页、多物料、分页表格、长文本和签章位置。

## 14. 首期验收标准

1. 客服能在 3 分钟内创建包含多个物料的业务单，选择模板和资料要求并复制客户链接。
2. 客户可在手机端分次填写；刷新、退出和重新打开链接后草稿不丢失。
3. 授权书变量和多物料表格正确渲染；签名或印章准确覆盖在允许区域，预览与最终 PDF 一致。
4. 审核员可逐项通过或驳回；客户只能修改驳回项目，回答、文件和审核历史可追溯。
5. 全部通过后系统锁定业务快照、生成最终 PDF，并立即关闭客户链接。
6. PM2 重启 API 和 Worker 后，业务数据、上传文件及未完成 PDF 任务可以恢复。
7. 后台页面权限由现有 Token 和角色映射控制，非授权角色不能越权查看或操作业务数据。
8. 客户链接、文件下载和敏感资料展示通过约定的安全测试。

## 15. 部署与配置

PM2 至少运行两个进程：API 和 PDF Worker。React 后台与 H5 构建为静态资源，由现有反向代理或 Node.js 静态服务发布。生产配置通过环境变量提供，包括数据库连接、鉴权接口、Token 请求头、文件根目录、外部访问域名、链接默认截止策略和日志级别。

上线前必须确认 PostgreSQL 备份、本地/NAS 文件备份、磁盘容量监控、日志轮转、HTTPS、反向代理上传限制和 Chromium 运行依赖。

- 增加更细的数据范围、统计报表和批量导出。
